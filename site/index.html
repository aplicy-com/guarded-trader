An AI trading bot that refused to trade

Guarded Trader lets an LLM research crypto strategies but never place an order. Every strategy it tested lost money at real fees, so its gates kept every one of them away from real money.

What it is

An execution and safety platform

Freqtrade does the trading. A second service, Conductor, keeps the ledger, enforces the capital rules and owns every halt, the kill switch and the alerts.

A research harness

Backtests run in a sandbox with no network: walk-forward validation, a random-entry null, Deflated Sharpe, and a registry that counts every trial, including the failures.

A public record

23 architecture decisions, a risk register, runbooks written to be followed at 2 am, drill results from the real server, and every research result.

Built around a one-time $100 principal that is never topped up, run by one operator in Canada. Not a signal service, not a product, not managed money.

The safety model

  1. The AI never places an order

    The LLM proposes and reviews strategy code. Only the deterministic engine talks to the exchange's order endpoints, and no LLM output has a path there.

  2. Two independent risk layers

    Freqtrade's own protections, plus Conductor's checks of daily loss, drawdown, loss streaks, deployed capital and correlated positions. Either one can stop trading.

  3. Only a human can resume

    A halt stays until a person clears it, with a confirmation code that expires in 60 s. Freqtrade always boots paused and starts only if no halt is active.

  4. The keys can't withdraw

    Exchange keys may query and trade, never withdraw or move funds. That is tested from the server, not assumed, and a venue whose key couldn't be proven unable to withdraw was rejected.

Quick start (dry-run)

Needs Docker with Compose v2 and GNU Make. No exchange key and no money: Freqtrade paper-trades against public market data.

git clone https://github.com/aplicy-com/guarded-trader.git
cd guarded-trader
cp .env.example .env
# Fill in only FREQTRADE__API_SERVER__USERNAME, __PASSWORD and
# __JWT_SECRET_KEY (any local values). Leave TRADING_MODE=dry_run
# and every exchange key empty.
make up      # Freqtrade + Conductor, bound to 127.0.0.1 only
make logs    # expect "Dry run is enabled"

The dashboard is at http://127.0.0.1:8000. Stop with make down. Going live is deliberately hard and gated; see the README.

Not financial advice

This is a research and engineering project. It has no proven trading edge, and its own published results show strategies losing money. Don't trade real money because of anything here. Crypto trading can lose all the money you put in.
